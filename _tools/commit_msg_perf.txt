继续优化：不碰泼溅观感，把重复劳动、显存浪费和主线程阻塞压下去

用户指令：「能不能继续优化，现在好卡，但是不能改高斯泼溅因为这效果已经很差了」。
所以这一轮一个像素的泼溅观感都没动，只治三样东西：**重复劳动 / 显存浪费 / 主线程阻塞**。

先把「卡在哪」量准（`_probe_frame_cost.gd`，离屏真窗口，关 vsync、不限帧；
探针把窗口最大化之后拿到了用户实机的 2800×1171，日志里也露出显卡是 RTX 4060 Laptop）：

    现状（全开 + 泼溅）  p50 13.05 ms   77 fps   957 draw   3052 MiB
    --splat=off          p50  5.06 ms  189 fps   975 draw    875 MiB
    关阴影 12.34 / 关后处理 12.46 / 关 MSAA 12.51 / 阴影+后处理全关 12.10

⇒ **泼溅一个人吃掉 +8.0 ms（整帧 61%）**；阴影只值 0.71 ms、后处理 0.59 ms、
MSAA 0.54 ms —— 不值得为这 1.8 ms 牺牲画面。

再用 `_probe_splat_scaling.gd`（扫缩放，配合只用于测量的 `--gdgs-skip-sort`）拆这 8 ms：
**基数排序 ≈ 3.9 ms 且与像素数无关**，投影+边界+raster ≈ 2.2 ms（700×280）到 5.7 ms（全分辨率）。

改动（四处，全部可回退）：

1. **静止帧复用**：相机 / 视口 / 光照 / 入场动画都没变的那一帧，整条 compute 链不跑，
   直接交回上一帧的纹理。判据是精确等价 —— `gsplat_render.glsl` 对每个像素都 imageStore
   （纹理全量重写），唯一的非相机输入 time 只喂入场动画。
   同进程 A/B：**11.37 ms（88 fps）→ 4.33 ms（191 fps）**。
   两个坑：① 不加光照容差完全无效 —— `day_minutes` 默认 20，太阳每帧都在动，
   relight 每帧上传，复用永远进不去；现在用 1e-3 的容差比较（≈0.057°）。
   ② 「入场动画落定」必须按数据里的 `time` 字段算，不能拍固定秒数；而且只统计
   `t <= now` 的（导出数据里有天文数字时间字段，会把 int() 撑溢出）。

2. **RenderState 缓存 4 → 2，且先淘汰再新建**：每个 state 自带一整套 1.28 GB 的泼溅缓冲，
   上限 4 就是 5.1 GB。`_probe_render_states.gd` 复现：换几次「3D 缩放」显存从 3052
   涨到 **6857 MiB**、帧时间 13 → 102 ms —— **用户报的「显存 6918 MiB / 开 1 就 7 fps」
   就是这个**。改完 state 数恒为 2、显存 4260~4424 MiB。

3. **大缓冲不填零**：`create_storage_buffer()` 原来给每个缓冲都准备等长零数组再交给
   `storage_buffer_create`，几百 MB 白做。`splats`/`culled_splats`/`sort_keys`/`sort_values`
   用之前都会被整份覆盖（排序只碰 `[0, element_count)`）。`init_gpu` 实测：
   **644 MB 732.7 ms → 25.9 ms**、456 MB 551.4 → 24.3、234 MB 257.6 → 19.8。
   `splat_lighting` 保持填零（没烘光照时会留垃圾）。

4. **换窗口不再阻塞主线程**：双缓冲 `user://campus_window_{a,b}.bin` + 后台 Thread 拼 bin
   （主线程一次都不停）；上传改成按时间预算 + 自适应块大小（单帧 550 ms → 1~6 帧、
   最坏单块 4~29 ms）；新纹理先清透明 + `main_sky.gdshader` 的 `fine_ready` 在细层
   没就绪时完全不采它；释放细层时把 quad 的纹理槽位临时指到粗层那张合法纹理。
   **换窗口最坏一帧 199~842 ms → 117~158 ms。**

验收（`_tools/run_shot.sh res://scripts/_verify_idle_skip.gd`）：

    抓图自证（同一帧连读两次）：逐字节相同 ✓
    噪声底（重算 vs 重算）：121655 字节不同（最大通道差 105）
    PASS：复用帧 vs 重算帧 = 0 字节不同
    结论：通过

最后那条「噪声底」是这轮最有价值的副产物：泼溅**本身就每帧都不一样** ——
GPU 基数排序按 key 分桶用原子操作，深度量化后大量高斯 key 相同、相对顺序不确定，
而 alpha-over 累加对顺序敏感。所以「逐字节相同」不是可用判据，得比噪声底；
这也顺带说明「留着上一帧的排序顺序不会比重新排更差」。
