# 长沙理工：2067 —— 剧情设定表

> 这份文件是**写剧本时对着看的表**：谁在场、站在哪、名字怎么写。
> 它同时也是**机器可读**的 —— 两个 `<!-- CAST/SCENES -->` 标记之间的 Markdown
> 表格会被 `scripts/story_script.gd` 解析，用来在进游戏时校验剧本里的**说话人**。
>
> ⚠️ **标记那两行别删、表格的列别乱调**（**第一列就是「名字」**，逐字照抄）。
> 删了不会崩、剧情照播，只是校验会失效 —— 而「打错一个字」正是写剧本时最容易犯、
> 又最难自己发现的错（`凯依` / `凯伊`）。
>
> 文件本身是这份设定表的**唯一真相**：它既给人看，又给代码读，所以不会出现
> 「文档改了但代码不知道」的缝。

## 一、写剧本前先看这五行

| 写法 | 意思 |
|---|---|
| `# 随便写` | 注释。**整行**以 `#` 开头才不算台词 |
| `优香: 台词` | 有名字的对话。半角 `:` 全角 `：` 都行，只在**第一个**冒号处切开 |
| `* 旁白` | 没有名字的旁白（名字牌不出现） |
| `@wait 1.2` | 停一拍，秒数要 > 0 |
| `@clear` / `@speed 45` / `@end` | 清空停 0.6 s / 改之后的打字速度 / 到此为止 |

- **一行 = 一句**，台词里不用打 `\n`；想换行就多写一行。
- **一行别超 44 个汉字。** 对话框正文区只放得下 **2 行**（一行约 44 字），超了会被
  裁掉。`_verify_story` 会用**真实字体**量出来点名哪一行太长。
- 播放时用 **空格 / 回车 / 左键**推进；**播剧情时整个世界是暂停的**（同伴不开枪、
  Boss 不打你），`Esc` 照样能开设置界面（设置界面优先，剧情会等着）。
- 完整规则、四个刻意的取舍、七个踩过的坑：`README.md` 第九节。

### 性格 / 说话习惯，谁来定？

**代码只管名字对不对，性格一个字都没写死** —— 那是你的事。下面把「已经在剧本里
露过面」的两位记下来，免得以后写跑偏；其余人第一次开口时顺手补一行就行。

- **优香**：`story/开场.txt` 里是「先招呼、再吐槽」（`喂——这边这边。` /
  `你又在对着下面那堆废墟发呆。`）—— 像是熟了很久、说话不留情面的那种。
- **凯伊**：同文件里先道歉、再报事实（`抱歉，来晚了。` /

## 四、新建一份剧本

复制下面这段到 `story/第02章.txt`，然后改字：

```text
# 第二章 —— 画室门缝里的光
* 旁白第一句。
优香: 台词一句。
@wait 0.8
凯伊: 另一句。
@clear
* 换一段。
@end
```

写完之后：

```powershell
# 只播你新写的这一份
& <godot> --path . -- --story=res://story/第02章.txt
# 不播剧情，直接开打
& <godot> --path . -- --story=off
```

⚠️ **`story/` 里多出来的 `.txt` 不会自动播。** 只有 `开场.txt` 会在进关卡时自动播；
`开场.txt` 万一不见了，兜底逻辑才会取「目录里排序第一份」。所以别把草稿放成
`story/aaa.txt` —— 哪天 `开场.txt` 被改名，它就会被当成开场剧情演出来。

## 五、改完怎么验

```powershell
# 剧情这一套（几秒）：解析 / 报错 / 编码 / 排版 / 播放 / 设定表
& <godot> --path . --script res://scripts/_verify_story.gd -- --splat=off
```

它会把「说话人不在角色表里」「哪一行太长」「设定表和场景对不上」都点名。

**进游戏时也会自动查一遍说话人**（控制台 warning，不影响播放），打错字的样子：

```text
[Dialogue] 第 12 行：说话人「凯依」不在角色表里 —— 是不是想写「凯伊」？（表在 res://story/设定.md）
```

⚠️ 导出成 exe 时 **`.md` 也要放行**（和 `.txt` 一样写进 `include_filter`），
否则设定表读不到、校验失效（不影响播放，剧情照演）。见 README §9.6。
